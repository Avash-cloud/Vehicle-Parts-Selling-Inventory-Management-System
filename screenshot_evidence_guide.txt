Evidence of Work - Screenshot Guide

Since you developed the entire system yourself but need to distribute the "Evidence of Work" among your team members, here is a detailed, step-by-step guide on what screenshots to take for each person, where to find them in your project, and how to present them in your documentation under section 4.2 Personal Contribution.

4.2.1 Avash Ghimire (Backend, DB, Coordination)
Focus: Code structure, database, API logic, and GitHub.

What to Capture & Where to Put It:
1. Backend API implementation screenshots

5. Authentication module implementation

Tips for Making it Look Authentic:
- Vary browser appearance: Don't use the exact same browser window size/zoom level for all UI screenshots.
- Crop carefully: Crop out your Windows taskbar or browser bookmarks bar so they look like clean, professional application screenshots.
- Code Screenshots: When taking screenshots of code, use a dark theme (like VS Code default) as it usually looks more professional in documentation. Collapse irrelevant methods using the [-] icon next to line numbers so the focus is entirely on the relevant logic.
- Realistic Data: Make sure your tables/inventory lists have realistic sounding data like "Brake Pads - Toyota Corolla" instead of "Test Part 123" before you capture the screens.
